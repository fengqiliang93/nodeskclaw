## 7. 跨分支复用指南

### 7.1 推荐迁移路径

1. 先迁移已提交基线（`7d0b6f8`）。
2. 再迁移当前未提交文件清单。
3. 最后执行“清理 -> 从 0 部署 -> 验收”三段式回归。

### 7.2 已提交基线迁移（推荐）

```bash
git switch <target-branch>
git pull --ff-only origin <target-branch>
git cherry-pick 7d0b6f8
```

### 7.3 未提交文件迁移（补丁方式）

建议在源分支先补齐为独立提交，再迁移；如果必须直接迁移文件：

```bash
git switch <target-branch>
git checkout v0.9.11-beta -- \
	nodeskclaw-artifacts/build-full.sh \
	nodeskclaw-artifacts/build-full.env \
	nodeskclaw-backend/app/services/channel_config_service.py \
	nodeskclaw-backend/app/services/deploy_service.py \
	nodeskclaw-backend/app/services/llm_config_service.py \
	nodeskclaw-backend/app/services/runtime/config_adapter.py \
	nodeskclaw-backend/app/api/llm_keys.py \
	nodeskclaw-backend/app/schemas/llm.py \
	nodeskclaw-backend/tests/test_codex_config_defaults.py \
	nodeskclaw-portal/src/views/OrgSettingsLlmKeys.vue \
	nodeskclaw-portal/src/i18n/locales/zh-CN.ts \
	nodeskclaw-portal/src/i18n/locales/en-US.ts
```

### 7.4 冲突处理优先级

1. `deploy/`：优先保留参数增强与同步逻辑。
2. `nodeskclaw-backend/app/services/`：优先保留代理转发与 runtime 适配。
3. `nodeskclaw-artifacts/`：优先保留 `TAG_COMPAT_ALIAS` 逻辑。
4. `nodeskclaw-portal/src/i18n/`：合并新增词条，避免覆盖其它语言修复。

## 8. 迁移后强制验收

至少完成以下 6 步：

1. `bash deploy/lan-access.sh reset-all --context <ctx> --lan-ip <ip>`
2. 按定制构建文档重建并导入 OpenClaw 双 tag。
3. `bash deploy/lan-access.sh bootstrap --context <ctx> --lan-ip <ip> ...`
4. `bash deploy/lan-access.sh sync-instances --context <ctx> --lan-ip <ip>`
5. `bash deploy/lan-access.sh verify-services --context <ctx> --lan-ip <ip>`
6. 执行 autosync 并确认 `success=3 failed=0`。

## 9. 快速审计命令

```bash
# 已提交定制范围
git --no-pager log --oneline origin/main..HEAD

# 合并基线文件清单
git --no-pager show --name-only --pretty=format: 7d0b6f8 | sed '/^$/d'

git --no-pager diff --name-only

# 运行态工件（建议忽略）
git status --short | grep -E '^.. (\.omc/|\.playwright-mcp/)'
```
