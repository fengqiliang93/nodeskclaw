## 5. 本轮关键定制主题

### 5.1 镜像构建与标签兼容

1. 新增 `TAG_COMPAT_ALIAS` 开关，默认开启。
2. 构建 `v2026.5.5` 时自动附带生成 `2026.5.5`，解决部署侧标签不一致导致的 `ImagePullBackOff`。
3. 形成“构建后导入双 tag”的标准动作，减少回归波动。

### 5.2 实例配置与通道同步稳定性

1. 强化飞书通道配置默认策略写入（dm/group policy）。
2. 强化模型配置链路（personal key 统一走 llm-proxy）。
3. 统一实例 runtime 配置适配，减少克隆/重建后配置偏移。

### 5.3 部署与访问链路稳定性

1. `deploy/lan-access.sh` 支持从清理到重建的一体化执行。
2. NodePort 与 Ingress 同步修复，支持“域名入口 + 局域网直连入口”双通路。
3. 通过 autosync 任务形成批量验收闭环。

### 5.4 OpenClaw v2026.5.18 升级与搜索能力固化

1. `build-full.sh` + 本地 OpenClaw 源码目录已形成固定构建口径。
2. `docker-entrypoint.sh` 从“删除整个 `plugins`”改为“精准清理失效托管残留”，避免误删合法 `searxng` 配置。
3. 后端配置写入链统一补齐 `tools.web.search` 与 `plugins.entries.searxng`，保证重启、克隆、reconcile 后仍保持搜索能力。
4. 形成“同 tag 重建必须配套 `imagePullPolicy=Always` + rollout 注解”的升级规则。
5. 现网已完成 45 个 OpenClaw AI 实例批量升级到 `v2026.5.18`，并通过 45/45 浏览器自动化验收。

## 7. 跨分支复用指南

### 7.1 推荐迁移路径

1. 先迁移当前单一 custom 合并提交。
2. 再迁移 OpenClaw `v2026.5.18` / SearXNG / 文档补充这一组新增文件。
3. 最后执行“清理 -> 从 0 部署 -> 验收”三段式回归。

### 7.2 已提交基线迁移（推荐）

```bash
git switch <target-branch>
git pull --ff-only origin <target-branch>
git cherry-pick <当前 custom 合并提交>
```

### 7.4 冲突处理优先级

1. `deploy/`：优先保留参数增强与同步逻辑。
2. `nodeskclaw-backend/app/services/`：优先保留代理转发与 runtime 适配。
3. `nodeskclaw-artifacts/`：优先保留精准清理 `plugins/channels` 与 SearXNG 默认配置逻辑。
4. `deploy/searxng/`：优先保留集群内 Service 名称与 baseUrl 一致性。

## 8. 迁移后强制验收

至少完成以下 6 步：

1. `bash deploy/lan-access.sh reset-all --context <ctx> --lan-ip <ip>`
2. 按定制构建文档重建并导入 OpenClaw 镜像，必要时补 `imagePullPolicy=Always`。
3. `bash deploy/lan-access.sh bootstrap --context <ctx> --lan-ip <ip> ...`
4. `bash deploy/lan-access.sh sync-instances --context <ctx> --lan-ip <ip>`
5. `bash deploy/lan-access.sh verify-services --context <ctx> --lan-ip <ip>`
6. 执行 autosync 并确认 `success=3 failed=0`。
7. 对全部 OpenClaw AI 实例执行 API + 浏览器自动化覆盖验收。
