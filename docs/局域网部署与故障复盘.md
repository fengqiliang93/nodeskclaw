# NoDeskClaw 局域网部署与故障复盘

本文档汇总本次部署中遇到的核心问题、根因、修复动作与可复用的局域网部署方案。

## 一、问题总览（按时间线）

| # | 现象 | 根因 | 处理结果 |
|---|---|---|---|
| 1 | 实例启动失败/拉不到镜像 | `image_registry` 仅配置到仓库前缀，缺少镜像名，拼接后变成错误地址 | 已修复为完整镜像路径，实例可拉起 |
| 2 | 实例域名访问 404/无路由 | Ingress `ingressClassName` 使用了 `nginx`，集群实际是 `traefik` | 已改为 `traefik` |
| 3 | 外部域名无法解析 | 域名无公网 DNS 记录，客户端无法解析到集群节点 | 通过 `IP/sslip.io` 路径规避；可选本机 hosts |
| 4 | Ingress 返回 502 | 实例 NetworkPolicy 未放行 `kube-system`（Traefik 所在命名空间） | 已放行 `kube-system` ingress |
| 5 | 页面白屏，控制台报 502 | `/sse/` 路由指向 9721，但容器未监听 9721 | 已将 `/sse/` 路由统一改到 18789 |
| 6 | HTTPS 访问 `ERR_CONNECTION_CLOSED` | 自签证书与客户端信任链不一致，且客户端不使用服务器 hosts | 已提供稳定 HTTP 入口；HTTPS 需正确客户端信任与 DNS |
| 7 | `LLM request timed out` | 实例 `openclaw.json` 中 `newapi.baseUrl` 错配为 `http://localhost:4511/newapi/v1`，容器内无该服务 | 已改为集群内 llm-proxy 服务地址 |
| 8 | `nodeskclaw-llm-proxy` 起不来 | 远端镜像拉取失败，导致 `ImagePullBackOff` | 已本地构建并导入 k3s containerd |
| 9 | 后续实例可能再次超时 | backend 环境变量仍为 `LLM_PROXY_URL=http://localhost:4511`，会回写错误配置 | 已修正 backend 环境变量并重启 |
| 10 | backend CrashLoop | 重新部署 backend 时 `INIT_ADMIN_ACCOUNT=admin`，但数据库中已存在自定义管理员账号，email 唯一键冲突 | 通过把 `INIT_ADMIN_ACCOUNT` 改为实际管理员账号修复；`lan-access.sh` 新增 `--admin-username` 参数永久固化 |
| 11 | personal key 配置的模型仍超时 | `llm_config_service.py` 中 personal key_source 直接使用用户配置的外部 baseUrl 写入实例，实例 Pod 同样无法直连外部地址 | 已修复代码：personal key 有 proxy_url 时同样路由到 llm-proxy |

## 二、最终稳定状态

1. OpenClaw 实例对外访问可走 LAN IP（不依赖公网 DNS）。
2. 实例 WebSocket 与聊天请求可达，`/newapi/v1/chat/completions` 返回 200。
3. `nodeskclaw-llm-proxy` 以集群内 Service 形式运行，实例统一走内网代理地址。
4. backend 的 `LLM_PROXY_URL`/`LLM_PROXY_INTERNAL_URL` 已与集群内 Service 对齐，避免回退到 `localhost`。
5. backend `llm_config_service.py` 已修复：org key 与 personal key 均路由到 llm-proxy，不再直连外部地址。
6. `deploy/lan-access.sh` 已新增 `--admin-username` 参数，`INIT_ADMIN_ACCOUNT` 与实际管理员账号保持一致，避免重新部署时 CrashLoop。

## 三、面向局域网访问的部署设计

目标：

1. 局域网任意电脑可访问 NoDeskClaw 控制台。
2. 局域网任意电脑可访问任意 OpenClaw 实例。
3. 镜像拉取失败时，可离线导入镜像并继续部署。

方案要点：

1. 控制台访问：使用节点 IP + NodePort（或现有 Ingress + 局域网 DNS）。
2. 实例访问：统一把实例 Ingress host 改为 `实例名.<LAN_IP>.sslip.io`，客户端无需 hosts。
3. 实例路由：强制 `ingressClassName=traefik`；`/sse/` backend 统一指向 18789。
4. 网络策略：确保实例命名空间允许来自 `kube-system` 的 ingress。
5. LLM 代理：实例 `newapi.baseUrl` 统一指向 `http://nodeskclaw-llm-proxy.nodeskclaw-staging.svc.cluster.local/newapi/v1`。

## 四、离线镜像导入标准步骤

当集群节点无法直接拉取公网镜像时：

1. 在可联网机器拉取镜像。
2. 导出为 tar 包（每个镜像一个 tar）。
3. 将 tar 包拷贝到集群节点。
4. 在集群节点导入 containerd：

```bash
sudo k3s ctr -n k8s.io images import /path/to/your-image.tar
```

5. Deployment 使用导入后的镜像名（建议 `imagePullPolicy: IfNotPresent`）。

## 五、执行脚本

已提供一键脚本：

`deploy/lan-access.sh`

它包含以下能力：

1. `import-images`：批量导入离线镜像 tar。
2. `ensure-llm-proxy`：部署/更新 llm-proxy，并修复 backend 的代理环境变量。
3. `sync-instances`：批量修复实例 ingress/class/sse/networkpolicy 与 `newapi.baseUrl`。
4. `show-urls`：输出控制台与实例访问地址（LAN + sslip.io）。

## 六、建议运维流程

1. 新集群首次部署后先执行 `ensure-llm-proxy`。
2. 每次新建/恢复实例后执行一次 `sync-instances`。
3. 镜像仓库不稳定时先走 `import-images` 再部署。
4. 若后续改动了 backend 环境配置，回归检查 `LLM_PROXY_URL` 不得为 `localhost`。
