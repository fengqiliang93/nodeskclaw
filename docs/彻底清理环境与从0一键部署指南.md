# 彻底清理环境与从0一键部署指南

## 1. 适用范围

本文用于以下场景：

1. 回归前需要把旧实例、旧镜像、旧配置彻底清理。
2. 从 0 重建 NoDeskClaw 与 OpenClaw 运行面。
3. 验证“构建-部署-实例-通道-同步”链路是否完整可用。
4. 作为跨分支迁移后的标准验收脚本。

## 2. 前置条件

1. 已确认 k3s context（示例：`default`）。
2. 已确认目标 LAN IP（示例：`<LAN_IP>`）。
3. 本机具备 Docker、kubectl、k3s、uv、npm。
4. 不修改 OpenClaw 源码，仅使用镜像构建与导入。

## 3. 步骤A：彻底清理环境

### 3.1 清理实例命名空间

```bash
kubectl --context default get ns | grep '^nodeskclaw-default-openclaw-' | awk '{print $1}' \
	| xargs -r kubectl --context default delete ns --wait=false
```

### 3.2 清理本地与 k3s 中的 OpenClaw 镜像

```bash
# 本地 docker
docker images | grep deskclaw-openclaw || true
docker rmi -f deskclaw-openclaw:v2026.5.5 deskclaw-openclaw:2026.5.5 2>/dev/null || true

# k3s containerd
sudo k3s ctr -n k8s.io images ls | grep deskclaw-openclaw || true
sudo k3s ctr -n k8s.io images rm docker.io/library/deskclaw-openclaw:v2026.5.5 2>/dev/null || true
sudo k3s ctr -n k8s.io images rm docker.io/library/deskclaw-openclaw:2026.5.5 2>/dev/null || true
```

### 3.3 一键清理平台状态（可选）

```bash
bash deploy/lan-access.sh reset-all --context default --lan-ip <LAN_IP>
```

## 4. 步骤B：从0重建镜像与平台

### 4.1 构建 OpenClaw 镜像（含 tag 兼容）

```bash
cd nodeskclaw-artifacts

./build-full.sh \
	--source-path ../openclaw \
	--version 2026.5.5 \
	--image deskclaw-openclaw:v2026.5.5 \
	--build-only
```

预期：构建日志出现 `Tag 兼容别名: true` 与 `已创建兼容 tag: deskclaw-openclaw:2026.5.5`。

### 4.2 导入 OpenClaw 双 tag 到 k3s

```bash
docker save deskclaw-openclaw:v2026.5.5 | sudo k3s ctr -n k8s.io images import -
docker save deskclaw-openclaw:2026.5.5 | sudo k3s ctr -n k8s.io images import -
```

### 4.3 构建并导入 backend/portal

```bash
docker build --platform linux/amd64 -t nodeskclaw-backend:local -f nodeskclaw-backend/Dockerfile .
docker build --platform linux/amd64 -t nodeskclaw-portal:local nodeskclaw-portal/

docker save nodeskclaw-backend:local | sudo k3s ctr -n k8s.io images import -
docker save nodeskclaw-portal:local | sudo k3s ctr -n k8s.io images import -
```

### 4.4 重启并等待工作负载

```bash
kubectl --context default -n nodeskclaw-staging rollout restart deploy nodeskclaw-backend
kubectl --context default -n nodeskclaw-staging rollout restart deploy nodeskclaw-portal

kubectl --context default -n nodeskclaw-staging rollout status deploy/nodeskclaw-backend --timeout=180s
kubectl --context default -n nodeskclaw-staging rollout status deploy/nodeskclaw-portal --timeout=180s
```

## 5. 步骤C：从0初始化与验收

### 5.1 平台初始化（如需）

```bash
bash deploy/lan-access.sh bootstrap \
	--context default \
	--lan-ip <LAN_IP> \
	--ingress-class traefik \
	--openclaw-image-registry deskclaw-openclaw \
	--openclaw-image-tag 2026.5.5 \
	--admin-username <admin-user> \
	--admin-password <admin-password>
```

### 5.2 同步实例访问入口

```bash
bash deploy/lan-access.sh sync-instances --context default --lan-ip <LAN_IP> --ingress-class traefik
bash deploy/lan-access.sh verify-services --context default --lan-ip <LAN_IP>
```

### 5.3 业务验收最小闭环

1. 使用你显式设置的管理员账号密码登录 Portal。
2. 配置或确认 `newapi` 模型提供商。
3. 按你本地维护的飞书 bot 配置表前 3 行创建实例。
4. 为 3 个实例写入飞书通道配置。
5. 触发 autosync 任务。
6. 验收条件：`completed` 且 `success=3 failed=0 pending=0`。

## 6. 多机集群附加要求

1. 目标镜像必须在每个可能调度节点可拉取或已导入。
2. 若离线导入，双 tag（`v2026.5.5` 和 `2026.5.5`）要在每个节点都导入。
3. 统一入口 IP 仍以部署机 LAN IP 为准，禁止直接使用 Pod IP 作为业务入口。

## 7. 常见失败与快速处理

### 7.1 ImagePullBackOff（tag 不一致）

现象：部署侧拉取 `deskclaw-openclaw:2026.5.5`，但本地只有 `v2026.5.5`。

处理：

1. 开启 `TAG_COMPAT_ALIAS=true`。
2. 构建后确认已生成非 `v` tag。
3. 导入双 tag 到 k3s。

### 7.2 实例记录存在但无运行 Pod

现象：实例列表在，autosync 报“无运行中的 Pod”。

处理：

1. 删除陈旧实例记录。
2. 重新创建实例并等待 `running + healthy`。
3. 再执行通道配置与 autosync。

### 7.3 飞书配置未正确落盘

处理：进入实例 Pod 检查 `/root/.openclaw/openclaw.json`，确认：

1. 有 `feishu` 节点。
2. 有 `dmPolicy: open`。
3. 有正确 `appId`。

## 8. 可复制的回归命令块

```bash
# 1) 清理
bash deploy/lan-access.sh reset-all --context default --lan-ip <LAN_IP>

# 2) 构建 openclaw
cd nodeskclaw-artifacts
./build-full.sh --source-path ../openclaw --version 2026.5.5 --image deskclaw-openclaw:v2026.5.5 --build-only

# 3) 导入双 tag
docker save deskclaw-openclaw:v2026.5.5 | sudo k3s ctr -n k8s.io images import -
docker save deskclaw-openclaw:2026.5.5 | sudo k3s ctr -n k8s.io images import -

# 4) 重建平台镜像
cd ..
docker build --platform linux/amd64 -t nodeskclaw-backend:local -f nodeskclaw-backend/Dockerfile .
docker build --platform linux/amd64 -t nodeskclaw-portal:local nodeskclaw-portal/

# 5) 导入平台镜像
docker save nodeskclaw-backend:local | sudo k3s ctr -n k8s.io images import -
docker save nodeskclaw-portal:local | sudo k3s ctr -n k8s.io images import -

# 6) 重启并验收
kubectl --context default -n nodeskclaw-staging rollout restart deploy nodeskclaw-backend nodeskclaw-portal
bash deploy/lan-access.sh sync-instances --context default --lan-ip <LAN_IP> --ingress-class traefik
bash deploy/lan-access.sh verify-services --context default --lan-ip <LAN_IP>
```

## 10. Agent 直接操作指南（可复制 Prompt）

### 10.1 一键执行“清理 -> 重建 -> 验收”

```text
请在当前仓库执行一次完整“彻底清理 + 从0重建 + 验收”流程。

参数：
- K8s context: <ctx>
- LAN IP: <lan-ip>
- OpenClaw 版本: <version>（示例 2026.5.5）

执行要求：
1. 先执行 reset-all。
2. 构建 OpenClaw 镜像时确保 TAG_COMPAT_ALIAS=true。
3. 导入双 tag（v<version> 与 <version>）到 k3s。
4. 重建并导入 backend/portal 镜像。
5. rollout restart backend/portal 并等待 ready。
6. 执行 sync-instances 与 verify-services。
7. 输出每一步的关键结果与失败重试信息。

约束：
1. 不修改 openclaw 源码。
2. 不执行任何 git push。
```

### 10.2 执行“最小业务闭环验收”

```text
请在部署完成后执行最小业务闭环验收。

目标：
1. 登录 Portal（账号 <admin-user>）。
2. 检查/配置 newapi 模型提供商。
3. 依据你本地维护的飞书 bot 配置表前 3 行创建实例。
4. 写入飞书通道配置。
5. 触发 autosync 并轮询状态。
6. 通过标准：completed 且 success=3 failed=0 pending=0。

输出：
- 3个实例最终状态
- autosync task id 与结果摘要
- 失败时的根因与修复建议
```

### 10.3 仅排查失败（不重建）

```text
当前环境出现部署异常，请只做排查，不做重建。

要求：
1. 收集：pods/events/logs/rollout 状态。
2. 核对镜像 tag 是否双态存在（v版本与无v版本）。
3. 核对实例记录与实际 Pod 是否一致。
4. 输出根因分级（高/中/低）与建议修复步骤。
5. 不执行破坏性删除操作，除非先征得确认。
```
